# DEC5: fixed temporal exposure, shared camera profiles, registered mesh texture

## What was tested

Implemented a separate opt-in pipeline on clever-shadow. It does not change the
existing PatchMatch, TSDF, Nerfacto, Splatfacto or fly-through defaults. The old
150-frame video is not regenerated by this experiment.

Output: `/mnt/data/lookcloser_dec5_5a3_joint_texture`.

- Source: immutable native linear EXR, all 62 train physical cameras. The three
  original held-out physical cameras are excluded from every color/UV fit and
  texture bake. Their RGB is read only after baking, for review.
- One **numeric** display exposure, `10.570320292648677`, is estimated once from
  train inputs and then frozen across cameras and time: exposure → Reinhard →
  sRGB. This is not the older `global` mode, which can recalibrate per dataset.
- One fixed three-channel multiplicative response per physical camera, shared
  across `000899, 000973, 001139, 001197`. These include different head poses.
  Channelwise mean log gain is constrained to zero to fix the gauge. The fitted
  gains range from approximately 0.852 to 1.168. These are relative fitting
  coefficients, **not measured sensor-response calibration**.
- `001059` is withheld from profile and shared-registration fitting. Only its
  local registration residual may adapt on train-camera RGB. An additional
  `000901` smoke test exercises the new-time adaptation entry point and verifies
  unchanged exposure/profile files.
- Per-time fixed meshes define 6,000 area-weighted common tangent patches with
  nine samples each. Mesh visibility and viewing angle determine eligibility;
  there are no person/face segmentation masks. Spatial blocks withhold roughly
  one fifth of patches from optimization.
- Optimize robust common log-linear patch colors, local contrast, 12×20 shared
  camera UV fields, and regularized per-time residual fields. Poses, intrinsics
  and mesh vertices stay fixed. Displacements are bounded by **2 native pixels
  per axis**, hence at most `2√2` pixels in vector norm; the original fit receipt's
  `maximum_native_shift_px` label was ambiguous. Later CLI requests name the
  per-axis bound explicitly. Observed holdout-point maximum norms: 1.89–2.37 px.
- Bake robust, angle-weighted mixtures of registered **linear train RGB** into
  a static UV texture. No runtime view selection, learned image generator or
  target-view correction. Depth-footprint checks reject unsafe source shifts.
  Only atlas gutters are dilated; unobserved surface texels are not painted over.
- `000973` reuses the earlier full-block TSDF correction, SHA-256
  `ab4436f42a2c047c1208a1912844743f8316f5b0b2acab897b624f89b32d23a9`.
  `001059` reuses its fly-through mesh. This study does **not** claim a new
  geometric reconstruction or a saved raw TSDF volume.

Entry points:

The convenience method `joint_temporal_texture.calibrate(...)` and its CLI action
`calibrate` now combine `prepare` and `fit`; `--dry-run` prints the ordered stages
without writing files or loading images. The method checks unique/disjoint times,
requires multiple fit poses and a held-out time, and rejects changed pinned runs
before preparation. It does not automatically bake or approve a reconstruction:

```bash
../.venv/bin/python scripts/joint_temporal_texture.py calibrate \
  --output /mnt/data/NEW_JOINT_RUN \
  --fit-frames 000899 000973 001139 001197 --held-frames 001059
```

The equivalent separate stages remain available:

```bash
cd /home/brans/repos/nerfstudio/LookCloser
../.venv/bin/python scripts/joint_temporal_texture.py prepare --output /mnt/data/NEW_JOINT_RUN
../.venv/bin/python scripts/joint_temporal_texture.py fit --output /mnt/data/NEW_JOINT_RUN
../.venv/bin/python scripts/bake_joint_temporal_mesh.py bake --output /mnt/data/NEW_JOINT_RUN --frame 000973
../.venv/bin/python scripts/bake_joint_temporal_mesh.py review --output /mnt/data/NEW_JOINT_RUN --frame 000973
```

For another time, reuse the fitted root without recomputing color or exposure:

```bash
../.venv/bin/python scripts/joint_temporal_texture.py prepare --output /mnt/data/NEW_JOINT_RUN --frames 000901
../.venv/bin/python scripts/joint_temporal_texture.py adapt --output /mnt/data/NEW_JOINT_RUN --frames 000901
../.venv/bin/python scripts/bake_joint_temporal_mesh.py bake --output /mnt/data/NEW_JOINT_RUN --frame 000901
```

Existing caches/configuration are hash-pinned. The original fitted root retains
its exact fitting source snapshot at `config/joint_temporal_texture_fit.py`;
later guard/adaptation additions intentionally change the fresh-fit request hash.
Do not rerun a changed fit into that root or silently overwrite its request.
Native cached RGB and GPU sampling are shared across camera observations; file
reads/hashes and raycasts use eight CPU threads. No new PatchMatch job was needed.

The JPEG converter additionally accepts the backwards-compatible opt-in pair
`--exposure-mode fixed --fixed-exposure-gain 10.570320292648677`. It never estimates
an image-dependent exposure in that mode. Existing converter defaults stay intact.
The joint texture pipeline itself reads original EXR, bypassing the old per-image
JPEG gains entirely.

## Results

### Independent RGB evaluation

Native held-out `F004_B005_1210O9`, one GT-only manual face-interior polygon per
time, identical across all variants, frozen display exposure. PSNR uses selected
RGB pixels; SSIM and AlexNet LPIPS use the tight face bounding box with both
images zeroed outside the same polygon. No candidate surface mask, room metric,
actor aggregate or loss is reported. Ear, hair and hand/tube are reviewed
separately. These values are **not numerically comparable** to the earlier
per-image-exposure campaign and its different face polygons.

| Time | Static atlas variant | Face PSNR ↑ | Face SSIM ↑ | Face LPIPS ↓ |
|---|---|---:|---:|---:|
| 000973 | Frozen exposure only | 27.2454 | 0.90195 | 0.12301 |
| 000973 | + fixed camera RGB profiles | 27.0824 | 0.90090 | 0.12731 |
| 000973 | + joint registration | 27.0533 | 0.90087 | 0.11761 |
| 001059 | Frozen exposure only | 28.0619 | 0.91536 | 0.12766 |
| 001059 | + fixed camera RGB profiles | 27.8242 | 0.91373 | 0.13203 |
| 001059 | + joint registration | 27.8363 | 0.91144 | 0.12623 |

Color correction alone worsens the held-out RGB metrics in both cases. Joint
registration recovers a small LPIPS advantage over the frozen-exposure control:
about 4.4% and 1.1%, while PSNR/SSIM remain slightly worse. This is **not an
across-the-board quality improvement**. The control uses the same robust static
atlas fusion; it is not the old target-dependent hard-source renderer.

### Cross-camera agreement and portable assets

Median absolute log-RGB disagreement on spatially withheld mesh patches:

| Time | Frozen exposure | Profiles only | Joint |
|---|---:|---:|---:|
| 000899 | 0.12542 | 0.11534 | 0.11308 |
| 000973 | 0.12899 | 0.11899 | 0.11367 |
| 001139 | 0.12994 | 0.11818 | 0.11179 |
| 001197 | 0.13205 | 0.11891 | 0.11265 |
| 001059 — profile holdout | 0.12209 | 0.10983 | 0.10453 |

This is an internal agreement statistic, not face quality: its common color is
computed from the observations being compared, even on the held-out patches.
The head-turn holdout supports modest transfer of the shared profile, not proof
that illumination/BRDF and true camera response have been uniquely separated.

Portable self-contained GLB and OBJ+MTL+texture ZIP are available for `000973` and
`001059` under `frames/<id>/`. GLB embeds a roughly 5K RGB texture, uses an unlit
material, and retains the original triangle inventory after a recorded rigid
centering/Z-up→Y-up transform. Geometry/UVs/embedded textures are checked on import.
Coordinates are normalized reconstruction units, not a claimed metric scan.
The primary `000973` mesh has 155,052 triangles and 12,719,763 sampled atlas texels;
174,978 surface texels have no accepted observation and are recorded, not hidden.

The first export had a serious UV failure: normalized tiny triangles were
treated poorly by the unwrap step, leaving only 154,939 sampled texels. Scaling
**only the unwrap input** to extent 100 corrected it; original geometry was not
scaled or sculpted. The rejected output is retained under `diagnostics/`.
See [xatlas packing/parameterization definitions](https://github.com/jpcy/xatlas/blob/master/source/xatlas/xatlas.h)
for the upstream coordinate/texel-scale API. A tiny-normalized-mesh regression
test prevents this particular failure from returning.

Native review verdict: **both assets fail the strict artifact-free criterion**.
They are delivered as inspectable experimental meshes, not approved repaired
surfaces. The hand/tube tip remains geometrically distorted/overextended; the
ear is smoother than GT; hair and silhouette retain ragged, sometimes
skin-colored triangles; a narrow under-chin gap is visible from the extra angle.
Room absence is ignored. Good mean agreement does not override these defects.

Tests: 33 passed, covering the new unit tests plus the existing campaign suite.
Contracts include fixed-exposure replay/resume, invalid gains, half-pixel
projection, gain gauge/recovery across changing content, per-axis UV bounds,
frozen-profile checksums, incomplete cache rejection, zero-weight fusion, tiny
mesh parameterization, and textured GLB round-trip.

The subsequent convenience-helper addition passes 42 tests in the same combined
suite, including prepare→fit ordering, a side-effect-free CLI dry run, invalid
time inventories, immutable source/output separation and early rejection of a
changed calibration request. No calibration, geometry or texture was regenerated
for this API-only addition.

## Insights

1. Separating fixed exposure from fixed **physical-camera** calibration works;
   head motion need not cause exposure re-estimation. New-time UV adaptation
   leaves the camera profiles unchanged. Temporal flicker over all 150 frames
   has not been measured in this two-asset demonstration.
2. Better multiview agreement does not guarantee a better held-out photograph.
   The estimated diagonal RGB profiles also absorb some view/material effects.
   They should not be promoted as a universal correction solely from the
   internal residual reduction.
3. The bounded registration provides a small perceptual benefit here. It does
   not identify or repair the wrong TSDF surface, disocclusions, or strong
   specular/view-dependent appearance. Static fusion cannot reproduce every
   view-dependent highlight, and it can soften details.
4. Native patch inspection is now available before committing to a video bake:
   `review_joint_temporal_texture.py inspect`. It displays common mesh-tangent
   patches from separate train cameras before/after correction and registration.
   The rejected samples are geometry visibility diagnostics, not segmentation.
5. No cosmetic GT painting or unsupported sculpting was used. The next distinct
   geometry experiment would need independent multiview evidence and should not
   be conflated with this completed color/registration implementation.
