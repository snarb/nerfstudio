## Training monitoring additions

Baseline runs can enable `--logging.csv-writer.enable True` to write compact `metrics_compact.csv` rows for train/eval trends, `best_eval_*`, plateau and overfit status, which is useful because recent 3k baselines plateau early and best checkpoint metrics are more informative than final-step metrics.

## Occupancy-grid defaults

Use the measured safe occupancy defaults unless a sweep explicitly overrides them: `grid_resolution=128`, `occupancy_grid_levels=1`, `render_step_size_mult=1.0`, `alpha_thre=0.0`, `transmittance_threshold=0.0`, `near_plane=0.01`, `cone_angle=0.0`, `occupancy_warmup_steps=4096`, and `occupancy_binary_warmup_steps=4096`. `occupancy_binary_warmup_steps` keeps binary occupancy fully occupied during cold start while `occs` continue updating; this prevents early grid pruning from permanently removing thin/peripheral detail. Do not use PSNR/SSIM/LPIPS or eval loss alone for artifact-sensitive runs: render saved checkpoints, run the artifact detector, and prefer checkpoints with `artifact_score=0.000` because normal metrics can select a checkpoint with a small structural artifact. For artifact-to-grid debugging, run `python scripts/debug_artifact_occupancy_grid.py --run-dir <RUN_DIR> --render-file <RUN_DIR>/renders_*/eval_img_0000.png --eval-index 0 --out-dir <OUT_DIR>`; it maps the largest artifact bbox pixels back to occupancy-grid voxels and reports whether the grid is likely missing them.

Current ARM artifact-isolation policy: do not run new no-ARM controls in this phase. The no-ARM occupancy-grid path is already known to reach `artifact_score=0.000`, so new experiments must keep ARM enabled (`ray_sampling_mode=adaptive`) and keep occupancy-grid sampling enabled. Keep FAS and Feature Reweighting disabled until the ARM-only artifact path is stable and variance-safe.

## Training-budget policy

Use `max_num_iterations=200000` as the default limit for future non-smoke LookCloser/ARM retests, unless an experiment explicitly needs a shorter diagnostic budget. Keep early stopping on eval-loss plateau enabled by default, but use the high cap so runs can continue past the previous `15188`/`90000` short budgets when validation loss keeps improving. Artifact-sensitive runs should save/eval enough checkpoints for `--eval-checkpoint artifact` over all three eval views, and reports must include train time.

LookCloser frequency-grid experiments use `scripts/run_lookcloser_preprocess_quiet.py` for dataset frequency-map generation, `scripts/run_lookcloser_quiet.py` for one quiet run, and `scripts/run_lookcloser_sweep.py` for 3-seed candidate sweeps. These mirror the bounded Instant-NGP protocol but add training-time capture, best-per-metric reporting, frequency-grid/FAS flags, and a hard preflight check for dataset `lookcloser_frequencies` unless explicitly bypassed for smoke tests. The preprocessing wrapper keeps the tuned visual settings from `experiments/preprocess_heatmap_hyperparameter_tuning_6k.md`: `patch_size=8`, `ssim_window_size=7`, and `high_frequency_level=13`. Full-HD dataset maps use `train_steps_per_level=1000` and `ssim_threshold=0.95`; single full-image checks found `0.97` over-assigned max level and `0.93` likely under-labeled high frequencies.

Experiment decisions consider SSIM, LPIPS, and PSNR together. Sweep reports rank by mean SSIM first, then mean LPIPS, then mean PSNR, with eval loss and training time used as supporting signals; no runs are rerun solely to backfill this policy.

Use `scripts/detect_structural_artifacts.py` as the automatic detector for serious structural artifacts in rendered crops or triptychs, especially broken/dislocated thin structures, holes, and floaters. Include its `artifact_score` alongside the current evaluation signals (SSIM, PSNR, LPIPS, and eval loss) when comparing candidate checkpoints; lower `artifact_score` is better and `0.0` means no qualifying severe local-SSIM artifact blobs. When needed, the script also saves bbox overlays, heatmaps, and suspicion maps for visual analysis of problematic artifacts. Nerfstudio `ns-eval` image outputs are side-by-side `GT|render`; the detector now crops the right render panel automatically when `--cand-file` is exactly twice the GT width and raises on any remaining shape mismatch to avoid false zero scores from comparing GT against the left GT panel.

The detector has explicit threshold presets. `--preset legacy` is the historical default and preserves old full-frame scores. `--preset significant` uses `ssim_severe=0.40`, `area_box=250`, `area_serious=250`, and `sev_min=0.85`; it was calibrated from component audits to ignore floor/edge/equipment detector floor while still firing on high-confidence hard structural failures. The quiet runner, ROI scorer, backfill utility, and artifact gate accept the same preset via `--artifact-detector-preset` or `--preset` depending on the script. Keep legacy scores in reports for continuity, and use significant-preset scores as the stricter “substantial artifact” scalar.

Manual guarded seed loops can be summarized with `scripts/summarize_lookcloser_runs.py <experiment_dir>` once all three `run_summary.json` files exist. The helper reads the selected best-eval-loss checkpoint summaries plus `metrics_compact.csv`, then emits per-run metrics, 3-seed means, and best single results for SSIM, LPIPS, PSNR, eval loss, artifact score when present, and train/eval/artifact/total runtime. `scripts/run_lookcloser_quiet.py` records those runtime fields plus git/data provenance in `run_summary.json` and runs the structural-artifact detector on `eval_img_0000.png` by default after final eval; pass `--artifact-render-names` for multi-view scoring or `--no-artifact-score` to skip it. LookCloser occupancy-grid tuning exposes nerfacc update knobs (`occupancy_occ_thre`, `occupancy_ema_decay`, `occupancy_warmup_steps`, `occupancy_update_interval`, optional update step size), occupancy AABB cascade levels, a mean-clamp multiplier, binary dilation, and `occupancy_binary_warmup_steps` for a dense occupied cold-start before pruning. Training metrics include occupancy ratio, `occs.mean/max`, effective thresholds, and binary flip counts. Set `ray_sampling_mode=occupancy` for constant-step nerfacc OccGrid traversal without frequency-aware subdivision or fixed full-ray sampling; `auto` preserves the old adaptive/fixed switch.

Use `scripts/debug_artifact_occupancy_grid.py` for artifact-driven occupancy debugging. Given a run/config and side-by-side eval render, it reuses the structural-artifact detector's largest bbox, projects sampled artifact pixels through the matching eval camera, queries surface-depth and along-ray voxels in the nerfacc occupancy grid, and writes JSON/Markdown plus an overlay. Treat `grid_miss_likely=true` as evidence to prioritize grid resolution, decay, dilation, handoff, and traversal-step experiments before field-capacity changes.

The artifact detector supports optional crop margins (`--crop-top/bottom/left/right`), and the quiet/sweep runners pass them through as `--artifact-crop-*`. Defaults are zero and preserve the official score. Margin scores are diagnostic only: for this scene they show a detector edge floor near `~1` for fixed rendering, while ARM artifacts remain higher under the same margins. Additional detector-audit flags (`--include-bbox`, `--exclude-bbox`, `--drop-border-components`, `--json-out`, `--print-json`) are available for ROI validation and saved bbox analysis; they must not be mixed into official runner scores unless the experiment report explicitly changes the scoring protocol. `detect_structural_artifacts.py` also reports `serious_artifact_score`, which accumulates only major/serious components; this is a broad regression metric, not a replacement for curated ROI, because floor/equipment texture components can still be major-area blobs.

Use `scripts/score_artifact_rois.py` for named high-value ROI artifact audits using the same detector thresholds on crop-gate regions. This is diagnostic, not a replacement for official full-frame artifact scoring. The standalone script defaults to the curated ROI list and accepts `--all-rois` for the broader debug set. `scripts/run_lookcloser_quiet.py` runs it after full-frame artifact scoring by default and stores the result under `artifact.roi` in `run_summary.json`; pass `--no-artifact-roi-score` to disable. The runner default `--artifact-roi-crop-names` is the same curated list and uses `fingers_right_tight_eval1` instead of the older broad `fingers_right_eval1`, because the broad crop can fire on hair/face texture rather than fingers. Pass `--artifact-roi-crop-names all` or explicit comma-separated crop names for broader debugging. `scripts/summarize_lookcloser_runs.py` reports ROI artifact score, ROI serious count, and stand-connector score when present. In `experiments/occupancy_improvements_repport.md`, ROI scoring showed fixed s640 has no serious stand-connector artifact across three seeds (`0.000` stand-connector ROI), while the best ARM checkpoint still has severe ROI failures (`4/9` serious ROIs, stand connector `4.105`). This makes ROI audit the preferred check before launching more occupancy-grid sweeps: only tune grid conservativeness when a meaningful ROI failure also maps to `grid_miss_likely=true`.

Use `scripts/audit_artifact_components.py` when the full-frame detector score and visual judgment disagree. It runs the same full-frame detector, then labels each detected component by overlap with curated ROIs and a stricter structural ROI bucket that excludes `floor_crack_eval0` by default. It writes JSON/CSV/Markdown and is explanatory only; the official score remains the raw full-frame detector score. Current audits show fixed s640 keeps structural ROI serious component score at `0.000` across seeds 42/43/44, while the best ARM checkpoint has nonzero structural serious component score, so remaining fixed full-frame score is mostly off-ROI floor/edge/equipment detector floor.

`scripts/run_lookcloser_quiet.py` also supports artifact-aware checkpoint selection with `--eval-checkpoint artifact` and `--eval-checkpoint roi`. These modes render every saved `step-*.ckpt`, run full-frame plus ROI artifact scoring, save all candidate evals under `artifact_candidate_evals` in `run_summary.json`, and select the checkpoint by structural-artifact score before quality tie-breakers. Use these modes with `--keep-all-checkpoints` on artifact-sensitive confirmation runs; `best` and `latest` preserve the previous eval-loss/latest behavior.

Use `scripts/summarize_artifact_gate.py` to produce a final artifact-gate bundle for a set of run directories. It writes JSON/CSV/Markdown with PSNR/SSIM/LPIPS, full-frame artifact score, full-frame serious score, curated ROI score, ROI serious score, stand-connector score, and structural component audit fields. The structural component fields come from the same detector components but bucket them by curated structural ROI overlap; they are explanatory and do not replace the raw full-frame score. Pass `--render-dir LABEL=...` and `--eval-json LABEL=...` when comparing multiple checkpoints from the same run, otherwise the artifact score and quality metrics can come from different checkpoints. In `experiments/occupancy_improvements_repport.md`, this gate shows fixed s640 has `ROI serious=0`, stand connector `0`, and structural serious component score `0` across three seeds, while the best ARM checkpoint has `ROI serious=7.209`, stand connector `4.105`, and structural serious component score `0.725`; the old full-frame score remains nonzero for fixed s640 because it includes floor/equipment/texture blobs.

Use `scripts/backfill_artifact_scores.py` when existing runs already have final renders but their `run_summary.json` lacks the current full-frame serious score or curated ROI block. The utility does not train or eval; it rescans saved `eval_img_000*.png` panels, writes the same `artifact` structure used by `scripts/run_lookcloser_quiet.py`, stores a `run_summary.json.bak-artifact-*` backup, and records `artifact_backfill` metadata. This keeps older confirmation runs comparable in `scripts/summarize_lookcloser_runs.py` without changing model checkpoints or renders.

Use `scripts/inspect_lookcloser_frequency_maps.py` after preprocessing to record map count, metadata count, level histograms, and max-level fraction before starting training sweeps.

Adaptive Ray Marching now uses a packed nerfacc-compatible path instead of the original Python per-step field-query loop. `FrequencyAwareVolumetricSampler` first traverses the occupancy grid at the adaptive max interval, then vectorizes paper-style interval subdivision from the frequency grid. The paper interval `1 / (2 * N_l)` is treated as normalized AABB/hash-grid distance and converted to ray `t` units with `dt = dt_norm / ||ray_dir / aabb_size||`. A scalar longest-side diagnostic produced indistinguishable crops from this per-axis AABB conversion and was rolled back. A packed linear-time distortion loss replaces padded max-step history for adaptive outputs. Isolated smoke with Frequency Grid on, Adaptive RM on, Feature Re-weighting off, and FAS off completed 16 iterations at 64 rays/chunk with no full-image eval; after startup, iteration time dropped to about `0.11s`, train samples averaged about `33` per ray, and saturation was `0`.

## Configurable LookCloser modules

The paper-level modules can be ablated independently through config flags.

- Frequency Grid: `pipeline.model.enable_frequency_grid` controls grid queries in the model; `pipeline.enable_frequency_grid` controls loading 2D maps and periodic grid updates. When disabled, the grid returns `fallback_frequency_level` and update steps are skipped.
- Current processed 3k data does not include `lookcloser_frequencies`, so Frequency Grid update experiments log a missing-map warning until the preprocessing path is restored.
- Feature Re-weighting: `pipeline.model.enable_feature_reweighting` controls Eq. 6 weighting in `LookCloserField`. When disabled, raw hash-grid features are passed to the MLP.
- FAS: `pipeline.datamanager.pixel_sampler.enable_fas` controls frequency-averaged pixel sampling. When disabled, `LookCloserPixelSampler` falls back to uniform `PixelSampler` behavior.
- Adaptive RM: `pipeline.model.enable_adaptive_ray_marching` controls adaptive ray marching. When disabled, `LookCloserModel` uses a fixed-step renderer with `fixed_num_samples_per_ray`.

Preprocessing now prefers `train_steps_per_level` over the legacy `steps_per_image`, so every frequency level receives enough optimization before SSIM assignment. The quiet wrapper currently calls `python -m nerfstudio.scripts.lookcloser_preprocess` directly so it does not depend on an installed console entrypoint.
