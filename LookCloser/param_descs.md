# LookCloser Parameter Notes

## Frequency Grid

Frequency Grid в LookCloser лучше понимать не как "еще одну большую hash-grid", а как карту сложности сцены.

Она отвечает на вопрос:

> В этой 3D-области сцены нужны только грубые низкочастотные признаки или здесь есть мелкие детали, для которых нужны высокочастотные уровни hash-grid?

Пример: гладкая стена - низкая частота. Тонкие провода, текст, мелкая фактура, края пальцев - высокая частота.

### Как она строится

1. Сначала изображения режутся на патчи.
2. Для каждого патча оценивается, какая частота нужна, чтобы его восстановить. Идея из бумаги: постепенно увеличивать частотность маленькой image-regression модели и найти минимальный уровень, где патч уже достаточно похож по SSIM.
3. Эта 2D-частота переводится в 3D через фокусное расстояние и глубину: `f_3D = f_2D * focal / depth`.
4. Один 3D-поинт может быть виден в нескольких изображениях, поэтому берут медиану частот по наблюдениям.
5. 3D-пространство делится на voxel grid. В каждой ячейке хранится частотный уровень, обычно максимум среди точек внутри ячейки.

То есть Frequency Grid хранит примерно такое:

```text
воксель (x,y,z) -> уровень частоты/detail level
```

### Как она обучается

Frequency Grid не обучается как обычные параметры MLP через backprop.

Основные параметры сцены все равно обучаются стандартно: hash-grid features + MLP оптимизируются по photometric loss между рендером и GT.

Frequency Grid скорее инициализируется и обновляется дискретно:

1. На старте ее заполняют из SfM point cloud и предобработанных частотных карт.
2. Во время обучения модель уже умеет предсказывать depth.
3. По depth для патча можно уточнить, куда этот патч попадает в 3D.
4. Соответствующая ячейка Frequency Grid обновляется, например через `max(old_level, new_level)`.

То есть она постепенно становится более точной картой того, где в сцене реально находятся мелкие детали.

### Для чего она нужна

Frequency Grid используется в трех местах.

1. Feature re-weighting.

Instant-NGP hash encoding имеет много уровней: низкие уровни кодируют грубую форму, высокие уровни кодируют мелкие детали.

Обычный Instant-NGP просто конкатенирует все уровни для любой точки. LookCloser делает иначе:

- если точка лежит в низкочастотной области, высокочастотные уровни приглушаются;
- если точка лежит в высокочастотной области, высокочастотные уровни используются сильнее;
- низкочастотные уровни не отключаются, потому что они нужны и для общей геометрии, и для деталей.

Идея: не тратить дорогую высокочастотную емкость на гладкие области.

2. Frequency-aware / averaged sampling.

Обычная случайная выборка пикселей почти равномерная. Тогда большая гладкая стена может получить намного больше обучающих лучей, чем маленький текст или тонкий кабель.

Frequency Grid и frequency maps позволяют чаще семплировать области с высокой частотой. В бумаге верхние частоты могут получать до примерно `3x` больше sampling probability, чем низкие.

3. Adaptive ray marching.

Для мелких деталей нужен меньший шаг вдоль луча. Если шаг слишком большой, луч может "перепрыгнуть" тонкие структуры, и результат размывается.

Frequency Grid говорит sampler-у: здесь можно идти крупнее, а здесь нужно плотнее.

### Почему это лучше, чем просто дать Instant-NGP максимум параметров

Просто увеличить hash-grid не решает главную проблему: модель не знает, где именно нужны эти параметры.

Большая grid дает больше capacity, но:

- емкость распределяется вслепую;
- высокочастотные уровни доступны и на текстах, и на гладкой стене;
- модель может тратить capacity на шум, экспозиционные отличия, view-dependent артефакты или гладкие области;
- hash collisions не исчезают магически;
- sampling остается проблемой;
- оптимизация становится тяжелее;
- больше параметров не равно больше правильных деталей.

Коротко:

> Максимальная Instant-NGP grid увеличивает мощность модели глобально.
> Frequency Grid управляет этой мощностью локально.

LookCloser не заменяет Instant-NGP hash-grid. Он добавляет над ней карту внимания: где использовать высокочастотные уровни, где семплировать плотнее, и где не тратить capacity.

## Interval Adjustment

Interval Adjustment в LookCloser - это часть adaptive ray marching: механизм, который меняет расстояние между sample points вдоль луча в зависимости от частоты области сцены.

Проще:

> Если луч проходит через гладкую стену, можно делать большие шаги.
> Если луч проходит через мелкие детали, текст, провода, тонкие края, шаг надо уменьшить.

### Почему это важно

В NeRF/Instant-NGP пиксель рендерится так:

1. Из камеры выпускается луч.
2. Вдоль луча берутся точки-сэмплы.
3. В каждой точке модель предсказывает density и color.
4. Эти значения интегрируются в итоговый цвет пикселя.

Если шаг между точками слишком большой, луч может просто "проскочить" тонкую деталь.

```text
большой шаг:
----x---------x---------x----
        тонкий провод
```

Сэмплы не попали рядом с проводом, модель получает слабый сигнал, и провод в рендере становится размытым, рваным или исчезает.

С маленьким шагом:

```text
маленький шаг:
----x--x--x--x--x--x--x----
        тонкий провод
```

Модель видит деталь точнее.

### Что делает Interval Adjustment

Frequency Grid говорит: в этой 3D-ячейке частота низкая или высокая.

Interval Adjustment использует это так:

- низкая частота -> можно брать более редкие сэмплы;
- высокая частота -> нужно брать более плотные сэмплы;
- пустое пространство -> можно пропускать через occupancy grid, как в Instant-NGP/nerfacc.

В бумаге идея связана с sampling theorem: чтобы восстановить деталь частоты `f`, частота сэмплирования должна быть примерно не меньше `2f`. Поэтому чем выше частота детали, тем меньше interval между соседними точками.

### Что оно дает

Главная польза: меньше размытия мелких деталей.

Особенно это важно для:

- тонких проводов;
- мелкого текста;
- sharp edges;
- фактуры;
- маленьких объектов;
- деталей, которые занимают мало пикселей.

Второй плюс: не надо везде увеличивать количество samples per ray.

Большая часть сцены обычно низкочастотная: стены, пол, крупные поверхности. Там плотные сэмплы почти ничего не дают.

Interval Adjustment пытается тратить больше сэмплов там, где они нужны, и меньше там, где они бесполезны.

### Чем отличается от Frequency Grid

Frequency Grid - это карта:

```text
где в сцене высокая/низкая частота
```

Interval Adjustment - это использование этой карты для ray marching:

```text
какой шаг делать вдоль луча в данной области
```

То есть Frequency Grid отвечает "где детали?", а Interval Adjustment отвечает "как часто там сэмплировать?".

### Почему это не всегда автоматически лучше

Если Frequency Grid в начале обучения неточная или геометрия еще плохо обучена, adaptive interval может навредить.

Например:

- модель еще не знает правильную depth;
- Frequency Grid пустая или шумная;
- sampler начинает слишком рано делать агрессивные маленькие/большие шаги;
- появляются underfit, шум или пропущенные поверхности.

Поэтому важен warmup: сначала дать модели собрать базовую геометрию обычным fixed sampling, а потом включать adaptive interval.

Коротко:

> Interval Adjustment нужен, чтобы ray marching был frequency-aware: гладкие области сэмплировать редко, мелкие детали сэмплировать плотно.

## Adaptive Ray Marching Parameters

Adaptive Ray Marching решает, с каким шагом идти вдоль луча.

Обычный fixed ray marching делает примерно так:

```text
луч:  x----x----x----x----x
      шаг одинаковый везде
```

Adaptive делает так:

```text
гладкая зона:      x--------x--------x
детальная зона:    x--x--x--x--x--x
```

В LookCloser это управляется частотой из Frequency Grid:

- низкий frequency level -> крупный шаг;
- высокий frequency level -> мелкий шаг;
- пустое/невидимое пространство сначала отсекается occupancy grid через nerfacc.

### Основные параметры

`enable_adaptive_ray_marching`

Включает adaptive path. Если выключено, используется fixed renderer с `fixed_num_samples_per_ray`.

`adaptive_min_step_size`

Нижняя граница шага. Не дает sampler-у делать бесконечно мелкие шаги.

`adaptive_max_step_size`

Верхняя граница шага. Не дает low-frequency или unknown зонам сэмплироваться слишком редко.

`adaptive_coarse_step_size`

Шаг первого, грубого прохода nerfacc occupancy traversal.

Это не финальный шаг для деталей, а шаг, которым ищутся потенциально занятые интервалы вдоль луча. Потом эти интервалы дробятся по frequency level.

Практически: уменьшение `adaptive_coarse_step_size` может помочь не пропускать тонкие объекты на первом проходе, но делает рендер дороже.

`adaptive_min_frequency_level` / `adaptive_max_frequency_level`

Ограничивают frequency level, который используется именно для расчета interval.

Они не меняют саму Frequency Grid, только говорят sampler-у: "для step size считай частоту не ниже/не выше этого уровня".

Например, `adaptive_max_frequency_level=12` означает: даже если grid говорит level 15, для размера шага использовать максимум 12. Это снижает число samples и стабилизирует training.

`adaptive_warmup_steps`

Сколько первых шагов обучаться fixed sampling-ом, прежде чем включить adaptive.

Это важно, потому что в начале density и Frequency Grid еще шумные. Если adaptive включить слишком рано, он может начать плохо сэмплировать еще не сформированную геометрию.

## Mapping Frequency Levels To Spatial / Hash-Grid Scale

Frequency level - это не просто метка "низкий/высокий". Он соответствует разрешению hash-grid уровня.

У Instant-NGP hash encoding есть уровни от грубого к тонкому:

```text
level 0  -> resolution 16      грубая форма
level 1  -> resolution ~24
...
level 15 -> resolution 8192    мелкие детали
```

В LookCloser эта шкала задается параметрами:

`min_res`

Минимальное spatial/hash-grid разрешение. Обычно `16`.

`max_res`

Максимальное разрешение. Для текущих HD maps важно `8192`.

`max_res_base`

Если `max_res` не задан явно, модель считает:

```text
max_res = round(max_res_base * scene_size)
```

где `scene_size` - это размер AABB сцены.

`num_frequency_levels`

Количество дискретных уровней. Обычно `16`.

Между `min_res` и `max_res` уровни идут геометрической прогрессией:

```text
level_to_freq(l) = min_res * per_level_scale^l
```

где:

```text
per_level_scale = (max_res / min_res) ^ (1 / (num_levels - 1))
```

Для текущего случая:

```text
min_res = 16
max_res = 8192
num_levels = 16
```

level 0 примерно соответствует `16`, level 15 соответствует `8192`.

Зачем это нужно для Interval Adjustment:

если level соответствует spatial frequency `N_l`, то нормализованный интервал берется примерно:

```text
dt_norm = 1 / (2 * N_l)
```

То есть чем выше `N_l`, тем меньше шаг. Это идея из sampling theorem: чтобы не потерять деталь частоты `f`, нужно сэмплировать минимум около `2f`.

В текущей реализации этот `dt_norm` считается в нормализованных AABB/hash-grid координатах, а потом переводится в ray `t` units с учетом размера AABB и направления луча. Это важно: иначе шаг был бы в неправильных единицах сцены.

## max_res Metadata In Frequency Maps

Frequency maps после preprocessing хранят не просто "level 13". Они хранят scalar-resolution frequency values, которые потом переводятся обратно в levels через metadata.

Metadata обычно содержит:

```text
min_res
max_res
n_levels
patch_size
stride
image_shape
```

Перевод примерно такой:

```text
level = round(log(freq_map / min_res) / log(per_level_scale))
```

Поэтому `max_res` в metadata критически важен.

Если frequency maps были сгенерированы с:

```text
min_res = 16
max_res = 8192
n_levels = 16
```

а модель запущена с:

```text
min_res = 16
max_res = 6144
n_levels = 16
```

то одно и то же scalar value будет интерпретировано как другой level. В итоге FAS, runtime grid updates, feature reweighting и adaptive interval будут думать о частотах по другой шкале.

Это не мелкая несовместимость, а смена смысла labels.

Поэтому в текущих HD runs с уже сгенерированными maps нужно явно держать:

```text
max_res = 8192
```

Особенно если меняется `scene_scale`. Если `max_res` не задан, модель выводит его из `max_res_base * scene_size`, и при другом `scene_scale` может получить, например, `6144` вместо `8192`. Тогда metadata validation правильно падает, потому что старые maps больше нельзя честно использовать.

Коротко:

- `adaptive step sizes` отвечают за то, как плотно сэмплировать луч;
- `frequency level -> hash-grid scale` отвечает за то, что level 12/13/15 физически означает в spatial resolution;
- `max_res metadata` гарантирует, что preprocessing maps и модель говорят на одной и той же frequency шкале.
