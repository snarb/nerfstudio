# Задание Codex: Luster girl, две секунды видео с чистого листа

## Цель и исходное состояние

Работай в ветке **`chinise_girl`**. Обучи отдельную LookCloser-модель на каждом
реальном кадре **000470–000529 включительно**. Исходная частота30FPS: это60 моделей
и ровно2 секунды. Отрендерь два видео1080×1920 — общий план и детали головы/верха
тела с фиксированных виртуальных камер. Движение должно приходить из60 исходных
кадров. Не заменяй модели повторением изображений или интерполяцией.

Новая машина имеет доступ к `ubuntu@dev3`; прежних локальных данных нет. Начни
новую кампанию, загрузи исходники и обучи модели заново. Основной входной скрипт:
`LookCloser/scripts/run_chinise_girl_video.py`. Он не требует прежнего локального
статического эксперимента, старых весов или путей `/home/brans`.

Прочитай `LookCloser/AGENTS.md`, локальную `LookCloser/Paper LookCloser.md` и отчёт
`LookCloser/experiments/luster_dataset_handoff.md`. Подробности прошлой работы:
`luster_000470.md`, `luster_video_000470_000529.md` в той же папке. Абсолютные ссылки
в исторических отчётах — адреса прежних артефактов, не обязательные локальные пути.

Предыдущая кампания не завершена: приняты14 моделей470–483, для484 выбран16k
после ухудшения на18k, финальный экспорт484 не сделан. Все60 частотных карт были
готовы. Первые10 кадров образовали лишь0.333 секунды превью. Не называй это
готовым двухсекундным видео. Исторические исключения численных порогов не дают
автоматического разрешения принимать заново обученные модели.

## Что уже находится в коде

Общие исправления в `main`: FP32 перед exponential и перед добавлением bias;
опциональное правильное преобразование направлений для TCNN SH; FAS сохраняет
соответствие camera/pixel/RGB при разных разрешениях, использует размер каждой
частотной карты и покрывает остаточные края изображения. Старые defaults сохранены.

В `chinise_girl` дополнительно оставлены:

- Опциональная supervised optical thickness для достоверного фона; .02 здесь.
- Маски, train-derived visual hull, AABB, render-only occupancy guard.
- Исследовательская совместимость density normalization; рецепт использует `none`.
- Перенос только параметров поля между соседними реальными кадрами; полный
  state только для продолжения того же кадра.
- Контроллер, оценки, визуальные отчёты, SHA256-проверяемое архивирование.
- Portable bootstrap и файлы `LookCloser/configs/chinise_girl/`: рецепт,
  train-derived нормализация и проверенный polygon cam011/frame475.

Предыдущие GPU-эксперименты проверяли модель и старый workflow. Новый bootstrap
проверен CPU-тестами, включая загрузку первого470 без локального reference,
проверку review/checkpoint, запрет подмены диапазона и реальную сборку короткого
видео. Полный GPU/SSH запуск нового bootstrap ещё нужно проверить на этой машине.

## Подготовка машины

Используй совместимое CUDA-окружение nerfstudio с Python≥3.10, PyTorch, nerfacc,
tiny-cuda-nn, OpenCV, scipy, Pillow, imageio-ffmpeg, psutil и зависимостями проекта.
`ffprobe`, `rsync`, `ssh` должны быть доступны в PATH. Репозиторий установи editable
в этом окружении (`python -m pip install -e . --no-deps`, если зависимости уже
установлены). Не заменяй работающий CUDA/PyTorch без необходимости. Для новой GPU
проверь совместимость установленных CUDA extensions с её архитектурой.

Если есть рекомендуемый env `/home/ubuntu/anaconda3/envs/nerfstudio`, используй
его; иначе выбери существующее совместимое окружение. Скрипт использует текущий
`sys.executable`, уважает `CUDA_HOME` и `TORCH_EXTENSIONS_DIR` и не задаёт пути
старой машины. Нужны достаточная RAM для165 HD views и свободный локальный диск:
практически выдели100GB или больше; набор исходников, HD-originals, частот и
checkpoint существенно больше финального видео. Число frequency workers можно
уменьшить с4 до1 при нехватке VRAM. Препроцессинг hull выполняется последовательно.

Проверь:

```bash
nvidia-smi
python -c 'import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name())'
ssh -o BatchMode=yes ubuntu@dev3 'test -f /fsx/tmp/luster/root_8s/bounds_8s.json'
```

Если `nvidia-smi` не работает и `/dev/nvidia*` отсутствуют, это может быть
ограничение окружения сессии. Не делай вывод о поломке GPU без проверки хоста.
В старой сессии одновременно пропали GPU device nodes, сеть и запись вне
песочницы. Именно это остановило работу, а не ошибка обучения модели.

## Запуск

Из корня репозитория выбери **новые** локальную папку и каталог архива на dev3.
Не используй архив прежней кампании как назначение новой.

```bash
python LookCloser/scripts/run_chinise_girl_video.py plan /data/chinise_girl_470_529 \
  --start 470 --end 529 --host ubuntu@dev3 \
  --archive-root /fsx/tmp/luster/chinise_girl_new_machine_470_529

python LookCloser/scripts/run_chinise_girl_video.py run /data/chinise_girl_470_529 \
  --start 470 --end 529 --host ubuntu@dev3 \
  --archive-root /fsx/tmp/luster/chinise_girl_new_machine_470_529 \
  --frequency-workers 4
```

Для smoke-run можно взять470–471 в **другой** папке и другом архиве. Не меняй
диапазон уже подготовленной кампании: изменится общий AABB и кадрирование. Скрипт
это запрещает. Короткий диапазон даёт честное короткое видео, не растягивается до2s.
Другой начальный кадр обучается cold с тем же расписанием; это требует новой
визуальной проверки, расписание измерялось на470.

Скрипт:

1. Проверяет CUDA/TCNN, SSH, source bounds, rsync, ffprobe.
2. Копирует165 calibrated RGB, per-frame poses/intrinsics и маски через dev3,
   сверяет remote/local SHA256. Никаких старых локальных файлов не требуется.
3. Делает HD subject-on-black, строит hull для каждого кадра, общий AABB и ROIs.
4. Применяет только проверенную source-hash-bound поправку cam011/frame475.
5. Перед каждым кадром обучает162 train-only frequency maps на локальной GPU.
   Не конкурирует ими с field training. Повторно использует только валидные receipts.
6. Обучает cold seed с обязательными native-review остановками; затем соседние
   модели с проверкой train-резкости после6000, проверкой сходимости и bounded polish. После каждого кандидата
   выполняет fine guarded export, сохраняет raw/guarded видеоизображения,
   архивирует checkpoint с проверкой SHA256 и запрашивает визуальную приёмку.
7. Собирает видео только после приёмки всех кадров. Проверяет разные field hashes,
   соответствие камер/PNG/checkpoint, длительность, число кадров, цвет и декодирование.

Exit code **2** означает обязательную визуальную проверку, а не crash.
`fresh_status.json` указывает кадр, run, checkpoint SHA и selection.
`live_check.json`, `supervision.jsonl`, `logs/`, `campaign_status.json` показывают
состояние. Внутренний supervisor пишет проверки каждые30s; сохраняй активный
контроль Codex и проверяй процессы/прогресс/GPU/OOM не реже часа. Не заканчивай
задачу просто потому, что команда работает отдельно.

## Как проходить visual gates

Посмотри полные train/eval views и native crops лица, глаз, рук, украшений,
границ платья; после первых temporal frames сравни их с предыдущими. Смотри
GT рядом с render. Thumbnail недостаточен для решения о резкости лица.
`visual_reviews/batch_*/` содержит обзорные листы; native PNG находятся в
`render_dir` из selection. Сравни raw и guarded virtual views на floaters и clipping.

Для промежуточного cold seed (и первого6000-step этапа каждого warm frame) после осмотра:

```bash
python LookCloser/scripts/run_chinise_girl_video.py review /data/chinise_girl_470_529 \
  --decision continue --reason 'Конкретные наблюдения о train/eval и динамике метрик' \
  --evidence /data/chinise_girl_470_529/frames/000470/runs/s008000/eval_008000/train_010_head.png
```

Вместо `continue` можно выбрать `export`, чтобы остановить fitting и проверить
финальный fine+guarded render выбранного checkpoint. `reject` сохраняет отказ.
Команда не смотрит изображения сама: решение должен принять Codex после осмотра.

Финальный gate принимает `accept`/`reject`, требует evidence и объяснение. Если
численный screen не пройден, принятие требует ещё `--allow-numeric-exception`.
Это исключение привязывается к SHA выбранного checkpoint. Не используй флаг
лишь ради продвижения очереди. После review повтори ту же команду `run`.
Она продолжит с сохранённого состояния, не перетренирует принятые модели.

Если качество плохое, не принимай кадр. Диагностируй данные, rays, маски, train
views; при необходимости используй отдельный `launch_luster_video_stage.py`
для обоснованного продолжения и повторный `finish_luster_video_frame.py`.
После замены выбранного checkpoint старые review/render receipts нельзя
переиспользовать. Старые результаты сохраняй отдельно. Скрипт запрещает молча
перезаписывать существующие stage outputs; после crash разбери checkpoint и
создай явное продолжение, а не удаляй run вслепую.

## Рецепт и ограничения решений

- Full-HD здесь означает long side1920, без crop:1406×1920 или1920×1406;
  выходное видео1080×1920. Eval012/095/150, train162, review011/097/151.
- Safe exponential + SH, normalization `none`, hash23/maxres8192,4096 rays,
  mixed precision, stable occupancy, fixed256 warmup4096; train coarse .001,
  export .0005/cap4096. Никакого перевода всей сети в FP32.
- Cold seed:8000→16000 (FR1)→24000 (FR.3)→28000→32000 (LR base .002 после24k).
  Принимать продолжение только после осмотра. Исторически выбран28000.
- Warm frame: параметрический старт из предыдущей принятой модели, LR .002,
  сначала6000 с eval4096/6000, дальше2000. Улучшение≥.07dB PSNR или≥.001 LPIPS
  позволяет продолжать; на плато сначала финальный экспорт. Один polish4000
  с половинным LR, бюджет24000. Плохое плато требует новой диагностики.
- Если train views сильно размыты, сначала исправь их. Frequency tuning не должен
  маскировать ошибки данных/семплирования. Если качество быстро и устойчиво
  растёт, можно обоснованно подождать или продлить, фиксируя решение.
- Метрики отчёта: PSNR/SSIM/LPIPS, также foreground PSNR и moving ROIs. Не loss.
  Выбор checkpoint: максимальный all-eval PSNR, LPIPS tie-break в пределах .07dB.
- Финальный numeric screen:30dB/.947/.060, foreground≥24. Ранее482/483 не прошли
  все три основных порога; их приёмка была компромиссом с остаточной мягкостью.
- SAM может сохранять студию между рукой и телом. Не изменяй eval targets для
  повышения метрик. Не вырезай движущуюся руку фиксированной полосой. Background
  plate subtraction повреждал чёрную вышивку — не применять его массово.
- Guard — явный train-hull prior при рендере; он не доказывает отсутствие
  артефактов в самом поле. Следи за clipping и сохраняй raw результаты.

видео,30FPS,2.000s,1080×1920; `final_video/{body_30fps,detail_30fps}.mp4`, metrics.csv,
manifest с hashes и успешным decoding/ffprobe. Осмотри сами видео на temporal
flicker, blur, floaters и обрезание рук/одежды. Обнови отчёт с ограничениями и
проверь архивирование кода, данных решений и финальных результатов на dev3.
Не объявляй отсутствие визуальных артефактов только по PSNR или ffprobe.
